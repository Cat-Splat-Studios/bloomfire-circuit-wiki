The Glossary

The words you meet in the code and the guides. Each has a one-line definition, its main type or file, and the page that explains it.

In 60 seconds

  • One entry, three parts. Each entry gives what the word means in this codebase, where it lives in code ("Main:") and where the full story is ("Explained in:").
  • Grouped by subject. Names, code, the adventure, matches, learning, networking, content, saves, and QA with documents. If you only have the word, use the §01 A–Z list.
  • Names are frozen. Many words survive from earlier products: Expedition, Isometric, EmberGrove. §02 says what each one names today.
  • Definitions, not rules. When a word is a rule or a procedure, the entry links the guide that owns it rather than restating it.
  • Linking a word. Any page can link a term as glossary.html#term-…, for example receipt.

02Product and project names

One game carries several names, because saves, preferences, the network fingerprint and published packages depend on old spellings. The product-name table owns the full list of frozen identifiers.

Bloomfire
The game's title. It is also the lane burst when Ember and Thicket terrain meet. Main: the title comes from Content/Circuit/locations.json, and the burst is CombatEventKind.Bloomfire in CombatRules. Explained in: Product names.
Bloomfire Circuit also: Bloomfire Circuit QA
The working product name of every player build. "Bloomfire Circuit QA" is the Android rehearsal build. Main: IsometricSliceBuild sets the name for each build and also names the Bloomfire Circuit editor menu. Explained in: Builds & Tools.
The Travellers' Circuit
The adventure, and the subtitle on the title page. Main: the rules are in CardForge.Circuit and the world in Game/EmberGrove/Assets/Runtime/Exploration. The Traveller* types are named after it. Explained in: World & Journal.
Ember & Grove
The former product name, now only the editor's identity. Main: productName in ProjectSettings/ProjectSettings.asset, which every build overrides, and the default pack's titles. Do not add new uses. Explained in: Codebase Tour §07.
EmberGrove
The code and data identity, kept for compatibility. Main: the Unity project Game/EmberGrove, the EmberGrove.* namespaces and preference keys, the pack Content/EmberGroveDefault (Id embergrove) and the EMBERGROVE_QA define. Explained in: Codebase Tour §07.
Expedition
The retired standalone mode. Its name survives on the hosted battle, the combat pack and the wire protocol. Main: ExpeditionApp, ExpeditionView, expedition-content.json, ExpeditionProtocol and the -expedition-* options. Explained in: Codebase Tour §07.
CardForge
The reusable toolkit and the creator tools. Main: the package com.catsplat.cardforge in Toolkit/Packages, the CardForge.* assemblies, and CardForge Content Studio in Tools/ContentStudio. Explained in: Codebase Tour §02.
Isometric also: the slice
A code name for the Circuit world, kept on purpose. Main: IsometricSlice (the world), IsometricSectorVisuals (its art), IsometricCombatBridge (into a match), IsometricSliceBuild (the build) and Tools/Package-Isometric.ps1 (the packager). Explained in: Codebase Tour §07.
CardGame
The repository. Main: Cat-Splat-Studios/CardGame. The relay ZIP is still named CardGame-Relay-*.zip. Explained in: Backup and restore.
Retired names also: Wildsignal, Lower Reach, SOTestCardGame
Earlier products whose names survive only as frozen identifiers. One example is the Id lower-reach-field-study in Content/Exploration/sector.json. Main: none. Explained in: Product names.

03Code and build units

Toolkit also: the package, CardForge package
The Unity package with the pure rules. All its runtime assemblies are free of the engine, except CardForge.Content. Main: Toolkit/Packages/com.catsplat.cardforge/Runtime. Explained in: Codebase Tour §02.
Adapter
Code that connects pure rule results to Unity: presentation, input, files and audio. An adapter never decides a rule. Main: IsometricSlice.Circuit.cs adapts CircuitRules, and CardForge.Content is the toolkit's file-loading adapter. Explained in: Source map.
Assembly-CSharp also: Assembly-CSharp-Editor
The game's one runtime assembly, made by Unity because the game has no .asmdef. It includes Assets/Tests. Main: everything under Game/EmberGrove/Assets except Assets/Editor, which becomes Assembly-CSharp-Editor. Explained in: Codebase Tour §04.
asmdef also: noEngineReferences
A Unity assembly definition file. noEngineReferences in one keeps its code from using Unity types. Main: the *.asmdef files in Toolkit/Packages/com.catsplat.cardforge. Explained in: Codebase Tour §02.
Partial file
One file of a C# partial class, named Type.Concern.cs. The suffix is the concern it covers. Main: the IsometricSlice.*, ExpeditionView.* and ExpeditionApp.* files. Explained in: Codebase Tour §06.
Result<T> also: the small monad
The value every rule returns: either a success value or a RuleError. Map transforms a success, Bind chains another step that can fail, and Match picks a handler. Main: the readonly struct EmberGrove.Result<T> in Runtime/Functional/Result.cs. Explained in: Rules Engine, Functional composition.
RuleError
Why a rule refused: a short Code and a player-readable Message. Main: Runtime/Functional/Result.cs. Explained in: Rules Engine.
RunResult, WorldResult
Older result types used by the toolkit's campaign rules, which the game no longer calls. They are separate from Result<T>. Main: Runtime/Progression/ExpeditionRun.cs and WorldProfile.cs. Explained in: Run and profile state.
CARDFORGE_HEADLESS
A compiler symbol set by the .NET tools. It swaps Unity's JSON for System.Text.Json and leaves out the Unity file loaders. Main: ExpeditionContent.cs and ContentPackFiles.cs; defined in Tools/ExpeditionRelay/ExpeditionRelay.csproj and Tools/ContentStudio/ContentStudio.csproj. Explained in: Codebase Tour §05.
CIRCUIT_QA, EMBERGROVE_QA
Compiler symbols that a rehearsal build adds, so the QA harnesses compile into that player and into no other. Main: IsometricSliceBuild.Build, and the #if lines at the top of Assets/Tests/Runtime/*.cs. Explained in: Codebase Tour §04, Builds & Tools.
UnityEngine stand-in also: UnityBoundary
A small file that declares TextAsset, Resources and JsonUtility in a fake UnityEngine namespace, so a .NET tool can compile the content parsers. Main: Tools/ContentStudio/UnityBoundary.cs and Tools/ExpeditionPerformance/UnityBoundaryStub.cs. Explained in: Codebase Tour §05.
link.xml
Tells IL2CPP not to strip the reflective serializer code that the network codec needs. Main: Runtime/Networking/link.xml, which CardForgeLinkerProcessor adds to every player build. Explained in: Codebase Tour §02.

04The adventure: Circuit, world and Waybook

Circuit also: the adventure
The solo adventure: walk the club's districts, play tables, collect cards and build decks. Main: CardForge.Circuit (CircuitDefinition, CircuitState, CircuitRules), adapted in the game by IsometricSlice.Circuit.cs. Explained in: World & Journal, Circuit rules README.
CircuitDefinition
Everything the rules need to know about the authored adventure: cards and tiers, starter presets, opponents, mentors, dialogue and the learning policy. Main: Runtime/Circuit/CircuitDefinition.cs. The game builds one in IsometricSlice.LoadCircuit. Explained in: Rules Engine.
CircuitState
A profile and run pair, so that permanent unlocks and a run's reward commit together. Main: CircuitDefinition.cs. The game holds it in the field IsometricSlice.circuit. Explained in: World & Journal.
Profile
What a player keeps forever: the card collection, saved decks, dialogue and event records, and the selected task. Main: CircuitProfile. Explained in: State and content.
Run also: day, outing
One seeded day of the adventure. It holds the districts, the active deck, the current location and any pending duel or reward. Main: CircuitRun. Explained in: State and content.
CircuitRules
The static, pure adventure rules. Each transition takes the definition and a state, and returns Result<CircuitState> without changing its input. Main: CircuitRules.cs (transitions), CircuitValidation.cs (Validate, Recover) and CircuitGraph.cs (districts). Explained in: Rules Engine.
ApplyCircuit
The one place the game accepts a new CircuitState. On failure it shows the error. On success it replaces the state and saves. If the caller required a save and the save failed, it puts the previous state back. Main: IsometricSlice.ApplyCircuit in IsometricSlice.Circuit.cs. Explained in: World & Journal, home §02.
IsometricSlice
The MonoBehaviour that runs the Circuit world: boot, walking, the camera, the Waybook, the journal, saving and starting matches. Main: 19 partial files in Runtime/Exploration/IsometricSlice*.cs. Explained in: World & Journal, Codebase Tour §06.
District also: stage
One stretch of the world, numbered by its stage: an arrival, venues and a tournament. Main: CircuitLocation.Stage, generated in CircuitGraph.cs, laid out by CircuitWorldLayout. Reusable district art is in prefabs bound by AuthoredCircuitDistrict. Explained in: World & Journal, World and tournaments.
Venue also: location, table
A place inside a district where something happens: a card table, a mentor, a card exchange or a workshop. Main: CircuitLocation and CircuitLocationKind in the rules. The art is built in IsometricSectorVisuals.Venues and .Authored. Explained in: World & Journal.
Room also: room revision
The authored geometry of a venue, kept by a stable Id and revision, so that old saves keep the room they had. Main: CircuitLocation.RoomId and RoomRevision, and the prefab component AuthoredCircuitRoom. Explained in: Supported Circuit world layouts.
Tournament also: champion
The last location in a district. Its matches end with a champion, and finishing the champion's reward opens the next district. Main: CircuitLocationKind.Tournament, and CircuitOpponent.Champion in the definition. Explained in: World and tournaments.
Sector
A tile grid with a start point and landmarks, the data that navigation runs on. Main: SectorDefinition and SectorNavigation (Validate, FindPath) in CardForge.Exploration. The start-up file is Content/Exploration/sector.json. Explained in: Start-up sector file.
Traveller
The player's figure walking the world. Main: IsometricSlice.Traveller, created by IsometricSectorVisuals.CreateTraveller. Explained in: World & Journal.
Lodge
The club lodge where the game opens. The title camera frames the notebook resting there. Main: LodgeWaybook.prefab and its LodgeWaybookBinding. The title camera is in IsometricSlice.Title.cs. Explained in: Arriving at the lodge.
Waybook
The book interface. On the title it is a menu written onto the lodge notebook with a world-space UI Toolkit panel. In the adventure it is the task book and its windows. Main: IsometricSlice.WaybookMenu.cs with Resources/UI/WaybookPage.uxml, then IsometricSlice.Waybook.cs and .CircuitUi.cs. Explained in: UI & Menus, the waybook guide.
Journal also: Circuit page
The modal windows over the adventure: map, cards, deck, rewards, dialogue, lessons, tasks and more. Each is a value of CircuitPage with a back stack. Main: ShowCircuit in IsometricSlice.Circuit.cs and DrawModal in IsometricSlice.Hud.cs. Explained in: World & Journal.
Task also: route web
An authored job shown in the Waybook's task list and route web, with a Go action that walks there. Main: CircuitTaskDefinition and CircuitRules.Tasks, drawn by IsometricSlice.Waybook.cs. Explained in: Task list and route web.
Event
A one-line conversation with up to three pictured answers, whose chosen answer the profile remembers. Its status goes Offered, then Presenting, then Committed. Main: CircuitEventDefinition, CircuitEventStatus, and CircuitRules.OfferEvent, BeginEvent and CommitEvent. Explained in: The Travellers' Circuit guide.
Episode also: friendly game, story match
A story match against a named friend. It grants no rewards. Main: CircuitEpisodeDefinition and CircuitRules.BeginEpisodeDuel, hosted as HostedSessionKind.FriendlyGame. Explained in: Hosted Sessions.
Visit also: story route
A story path that opens a later district early, after a committed event. Main: CircuitVisitDefinition and CircuitRules.OpenVisit; the game walks there in IsometricSlice.World.cs. Explained in: World and tournaments.
Club opening
The voiced first arrival: meet the club, choose a badge and nickname, then go to the first practice. Main: CircuitOpeningDefinition, drawn by IsometricSlice.Onboarding.cs. Explained in: First steps.
Saved deck also: Your decks
A named deck kept on the profile, separate from the run's own copy. Starting a run from it copies it into the run. Main: CircuitDeck, CircuitRules.CreateDeck, StartFromDeck and SaveRunDeck, edited in IsometricSlice.DeckBuilder.cs. Explained in: Saved decks.
Pending duel
The match the run is waiting on. It is set by BeginDuel and cleared by ResolveDuel. A save that still has one at start-up resolves it as Interrupted. Main: CircuitRun.PendingDuel (a CircuitDuel), and IsometricSlice.RestoreCircuit. Explained in: World & Journal.
Receipt
An Id attached to one duel attempt or event, so that delivering the same result twice changes nothing the second time. Main: CircuitDuel.ReceiptId, passed to IsometricCombatBridge.Play and back into CircuitRules.ResolveDuel. Explained in: Outcomes and receipts.
Duel outcome
How a match ended for the adventure: Won, Lost, Abandoned, Interrupted or Drawn. Main: CircuitDuelOutcome. Explained in: Outcomes and receipts.

05Matches and hosted sessions

Combat core
The pure card-battle rules. Main: the assembly EmberGrove.Expedition in Runtime/Core: CombatContracts.cs, CombatRules.cs and CombatAi.cs. Explained in: Rules Engine.
CombatRules.Resolve also: the reducer
Takes a full match state and one command, and returns Result<CombatResolution>: a new state plus ordered events. A rejected command leaves the input untouched. Main: Runtime/Core/CombatRules.cs, next to NewMatch and LegalCommands. Explained in: Rules Engine, One accepted command.
CombatState
The whole match: both sides, every card, terrain, turn and round. It is never saved. Main: CombatContracts.cs. The game holds it in ExpeditionApp.State, and the network authority holds its own copy. Explained in: Rules Engine.
CombatCommand
One player action: Play, Attack, Move, EndTurn or Concede (ActionKind), with source, target, lane and rank. Main: CombatContracts.cs. Explained in: Rules Engine.
CombatEvent
One thing that happened during a resolution, such as Draw, Damage, Death, Terrain or Bloomfire. The view animates these after the fact. Main: CombatEventKind in CombatContracts.cs; animated by ExpeditionView.AnimateEvents. Explained in: UI & Menus.
Catalog
The card definitions a match is played with. Main: Catalog in CombatContracts.cs, built by ContentPack.CreateCatalog. Explained in: Content & Media.
CardQuery
The one card sort, search and trait test that every card list uses. Main: CombatContracts.cs. Explained in: Source map.
CombatAi also: the rival
Chooses the computer opponent's next command and describes its intent. Main: CombatAi.Choose and DescribeIntent in Runtime/Core/CombatAi.cs, called from ExpeditionApp.Update. Explained in: Rules Engine.
Pulse, Momentum, terrain
Rule words. Pulse is the per-turn budget, Momentum is a bonus earned within a turn, and terrain is Clear, Thicket or Ember on a lane. Main: SideState.Pulse, CombatConfig.PulsePerTurn and TerrainKind. Explained in: Game rules.
Hosted session
A complete ExpeditionApp created for one screen, whether a duel, practice, lesson, Versus or Settings. It is put on a "Hosted session" object and destroyed when it ends. Main: IsometricCombatBridge.Begin. Explained in: Hosted Sessions.
HostedSessionKind
What a hosted session is: CircuitDuel, FriendlyGame, Practice, Lesson, Versus or Settings. It is set before the session starts and does not change. Main: ExpeditionApp.Session.cs. Explained in: Hosted Sessions.
IsometricCombatBridge
Hosts one session from the world. It configures the session by kind, waits until the session resolves, releases it, restores the world's runtime settings, then reports the outcome. Main: Play in Runtime/Exploration/IsometricCombatBridge.cs. Explained in: Hosted Sessions.
ExpeditionApp
The coordinator of a hosted session. It loads the pack, holds the CombatState, schedules the rival, polls the network and applies settings. Main: 10 partial files, Runtime/ExpeditionApp*.cs plus WorldTableContext.cs. Explained in: Hosted Sessions.
ExpeditionView
The hosted session's screens. It builds the board and menus, routes input, and animates accepted commands and events. Main: 23 partial files, mostly Runtime/ExpeditionView*.cs. Explained in: UI & Menus.
Versus also: friend play, LocalDuel
The friend-play menu. From it you start a shared-screen match (LocalDuel) or a network match. Main: HostedSessionKind.Versus and ExpeditionApp.ConfigureWorldMenuSession; opened by IsometricSlice.OpenVersusFromTitle. Explained in: Hosted Sessions.
World table also: living table, the actual table
When a match is played at a venue, the board is drawn on the table in the world rather than on a flat screen. Main: WorldTableContext, ExpeditionView.WorldTable.cs, WorldTablePresentation, LivingTable.prefab, and the camera in IsometricSlice.Table.cs. Explained in: The actual table, Hosted Sessions.
Preparation also: opening choice, FairMatchSetup
An optional solo opening benefit (Momentum, Shield or scouting) chosen before a match, at most one at a time. Main: IsometricSlice.Learning.cs (ChooseCircuitPreparation) and FairMatchSetup in ExpeditionApp.Session.cs. Explained in: Circuit fair-duel initialization checks.
DuelUi
The static factory that builds uGUI controls in code. It also holds MenuColour, MenuType and MenuSpace. Main: Runtime/DuelUi.cs, namespace EmberGrove. Explained in: UI & Menus.
Menu palette
A named set of menu colours in the pack's media theme, which can be tried without editing the pack by launching with -menu-palette <id>. Main: MenuPaletteDefinition in ContentPackFiles.cs, and DuelUi.MenuColour. Explained in: Menu roles, Content & Media.

06Learning: practice and lessons

Practice
The original first game: a scripted introductory match, with a spoken guide, that Learn to play starts. Main: Content/Circuit/practice.json and ExpeditionApp.ConfigurePracticeTutorial (ExpeditionApp.Practice.cs), hosted as HostedSessionKind.Practice. Explained in: Practice and the real adventure, Hosted Sessions.
Lesson
An authored topic in the Learn window: reading pages, plus an optional practice scenario played with the real combat rules. Main: LessonLibrary and LessonDefinition in Content/Circuit/lessons.json, checked and prepared by LessonRules (CardForge.Lessons), hosted through ExpeditionApp.ConfigureAuthoredLesson as HostedSessionKind.Lesson. Explained in: The lesson workshop, Hosted Sessions.
Practice vs lesson
Two tutorial systems with separate files and code paths. A practice comes from practice.json, a lesson from lessons.json. BasicPracticeLesson links the first lesson topic to the original practice, so it is not authored twice. Main: ExpeditionApp.Practice.cs and ExpeditionApp.Lessons.cs. Explained in: The lesson workshop, Findings.
PracticePath
The authored order of practices that Continue learning follows. Main: PracticePath in Runtime/Core/LessonContracts.cs, used by IsometricSlice.Onboarding.cs. Explained in: The lesson workshop.
Spoken guide also: PracticeNarration
Recorded instructions played during a practice. They are optional, and the text stays on screen when a recording is missing. Main: Runtime/PracticeNarration.cs and Content/Circuit/Voice/lines.json. Explained in: Spoken guide.

07Networking

Authority
The side that holds the full match and resolves every command. It checks seat, sequence, revision and fingerprint, and sends each seat only what that seat may see. Main: ExpeditionAuthority (Receive, ViewFor) in Runtime/Networking/ExpeditionAuthority.cs. It runs in the host's session for LAN and relay games, and in TrustedMatchApplication for the trusted service. Explained in: Networking, Current authority boundaries.
Seat
Player 0 or 1 in a network match. A LAN or relay host is seat 0. Main: ExpeditionNetworkSession.Seat, and the seats inside ExpeditionAuthority. Explained in: Networking.
Fingerprint
A hash of the catalog, deck presets and combat settings. Both players must match it before they can play. Main: ExpeditionFingerprint.Compute in ExpeditionAuthority.cs. ExpeditionProtocol.RulesVersion is one of its inputs. Explained in: Networking.
Wire packet, wire view
The network message types: a command envelope going in, and a per-seat view coming back. They are serialized with DataContractJsonSerializer. Main: WirePacket, WireCommand, WireView and ExpeditionWireCodec in NetworkContracts.cs. Explained in: Networking.
Projection also: snapshot, redaction
A seat's view turned back into a local CombatState. The opponent's hidden cards stay hidden. Main: ExpeditionProjection.ToSnapshot, which produces an ExpeditionSnapshot, presented by ExpeditionApp.PresentNetwork. Explained in: Multiplayer authority and privacy.
ExpeditionNetworkSession
The one client-side session type for every transport: LAN, relay, named rooms, the trusted service and the table lobby. Main: Runtime/Networking/ExpeditionNetworkSession.cs (Submit, Poll), with TcpNetworkLink and WebSocketNetworkLink. Explained in: Networking.
LAN
A direct TCP match between two players on one network, where the host is the authority. Main: HostLan and JoinLan on ExpeditionProtocol.DefaultPort. Explained in: Networking guide, Networking.
Relay
A WebSocket server that only forwards bytes between two players. The host stays the authority. Main: Tools/ExpeditionRelay (RelayApplication: /health, /relay), with the Windows companion EmberGroveRelay.exe; on the client, HostRelay and JoinRelay. Explained in: Networking, relay README.
Named room
A public or private relay room that players find by name instead of a code. Main: HostNamedRelay, JoinNamedRelay and ListRelayRoomsAsync; the menus are in ExpeditionView.Connection.cs. Explained in: Named-room protocol 3.
Trusted service also: trusted authority, SERVER mode
The relay started with --authority. It runs the authority itself, so neither player holds the full match. It listens on loopback only. Main: Tools/ExpeditionRelay/TrustedMatchApplication.cs (routes under /authority); on the client, CreateTrusted, JoinTrusted and ReconnectTrusted. Explained in: Trusted service proof, Networking.
Quickmatch
An unranked search for an opponent on the trusted service, using a preset deck. Main: ExpeditionNetworkSession.QuickmatchTrusted and CancelQuickmatch; the route /authority/quickmatch. Explained in: Networking.
Table lobby
A shared authored room where visitors walk to a table, wait, and challenge each other into a match. Main: IsometricSlice.OpenTableLobby (IsometricSlice.Versus.cs), ExpeditionNetworkSession.JoinLobbyTrusted and ExpeditionApp.AttachLobbyMatch; the service is started with --lobby. Explained in: Table lobby prototype, Networking.
Private relay QA
A one-off pair of QA builds, for Windows and Android, that carry an access key for a private relay. The key goes into an ignored, generated source file and is never committed. Main: Tools/Build-PrivateNetworkPair.ps1, the define EMBERGROVE_PRIVATE_RELAY_QA, and Assets/Tests/Runtime/PrivateRelayQaSettings.generated.cs (ignored). Explained in: Android development build, Builds & Tools.

08Content

Content pack
A folder of authored data. A manifest names a combat document, a world document, a media catalog and optional Circuit dialogue. Main: Content/EmberGroveDefault, loaded by ContentPackFiles.Load into a LoadedContentPack. Explained in: Content & Media, PACK_CONTRACT.md.
Manifest
The pack's manifest.json: its Id, versions and the names of its documents. Main: ContentManifest and ContentPackFiles.ParseManifest. Explained in: Content & Media.
Combat document
The cards, encounters, deck presets and match rules. Main: expedition-content.json, parsed by ExpeditionContent.Parse into a ContentPack. Explained in: Content & Media.
World document
World and campaign data for the toolkit's campaign rules. The game still loads and validates it with every pack. Main: world-content.json, parsed by WorldContent.Parse. Explained in: Content & Media.
Media catalog
The pack's images and audio with their Ids, the menu theme and palettes, and the art roles. Main: media.json, read as MediaDefinition in ContentPackFiles.cs. Explained in: Content & Media.
Circuit dialogue
The adventure's speakers and lines, events, episodes, visits and tasks. Main: circuit-dialogue.json, read as CircuitDialogue and checked by CircuitRules.ValidateDialogue. Explained in: Dialogue format.
Sidecar
A Circuit file that ships beside the pack rather than inside it: card-guide.json, locations.json, journey.json, practice.json or lessons.json. Main: Content/Circuit. IsometricSliceBuild.CircuitSidecars stages them, and IsometricSlice.LoadCircuit reads them. Explained in: Codebase Tour §08, Content & Media.
Card guide
Teaching data for each card: archetype, lesson, strength, weakness and unlock order. It must describe every card exactly once. Main: Content/Circuit/card-guide.json, read as IsometricSlice.CircuitGuide. Explained in: Circuit card design.
Staging also: StreamingAssets
Validating Content/ and copying it into the ignored Assets/StreamingAssets, on every build or on request. Never edit the staged copy. Main: StageEncounterContent, StageCircuit and StageSector in IsometricSliceBuild.cs, and Bloomfire Circuit ▸ Stage content for editor. Explained in: Codebase Tour §08, Content & Media.
Content root also: ContentOverride, -content-pack
The folder a player loads its pack from: -content-pack first, then persistentDataPath/ContentOverride if it has a manifest, then the staged pack. Main: ContentPackFiles.DefaultRoot. Explained in: Content & Media.
Combat hash
The SHA-256 of the combat document. Trusted matches use it to admit only players with identical content. Main: ContentPackFiles.ActiveCombatHash and LoadedContentPack.CombatHash. Explained in: Content & Media, Networking.
Content Studio also: CardForge Content Studio
The standalone Windows editor for cards, the club opening, narrative and media data. It needs no Unity. Main: Tools/ContentStudio, built as EmberGrove.ContentStudio.exe and started by Start-Studio.ps1. Explained in: Content & Media, Content Studio README.
CircuitStudio
Browser pages for simulating dialogue branches (index.html) and authoring lessons (lessons.html). Main: Tools/CircuitStudio. Explained in: Find the right tool.
Current Card Workshop
A Unity editor window that maps models and animation clips onto the real card catalog. Main: CurrentCardWorkshop in Assets/Editor/CurrentCardWorkshop.cs, opened from CardForge ▸ Current Card Workshop. Explained in: Current card catalog and Unity workshop.
CardArtworkCache also: lease
Loads card artwork from the pack and hands it out as leases, which are released when a screen is done with it. Main: Runtime/CardArtworkCache.cs (Acquire, Lease). Explained in: Content & Media.

09Saves and settings

CircuitSave
The game's save file around a CircuitState. It adds world position, camera, accessibility choices, the club name and badge, and lesson progress. Main: CircuitSave in Runtime/Exploration/CircuitPersistence.cs, filled by IsometricSlice.CaptureCircuitSave. Explained in: Saves & Settings.
CircuitPersistence
Reads and writes the save file. On restore it tries bloomfire-circuit-v2.json, its .previous, then bloomfire-circuit-v1.json and its .previous. A save written by a newer version blocks writing. Main: Runtime/Exploration/CircuitPersistence.cs. Explained in: Saves & Settings, Run and profile state.
PlayerSettings
The local, versioned player preferences: sound, display, reading and controls. Main: PlayerSettings and PlayerSettingsRules in Runtime/PlayerSettings.cs, stored by ExpeditionApp.Settings.cs in PlayerPrefs under EmberGrove.PlayerSettings.v1. Explained in: Saves & Settings.
Testing save
In a QA player, a separate save that owns every card, kept in a testing-all-cards folder so the tester's own save is untouched. Main: CircuitSliceChecks.TestingAllCards and TestingSaveFolder (CircuitSliceChecks.Saves.cs), turned on with -circuit-all-cards or from Settings ▸ Controls. Explained in: Tests README, Saves & Settings.
Playtest report
An optional local recording of one play session, written only after an explicit start. Main: PlaytestSessionService in Runtime/PlaytestSessionService.cs, writing Playtests/playtest-<id>.json under persistentDataPath. Explained in: Local playtest recording, Saves & Settings.

10QA, builds and documents

Rehearsal
An automated run inside a real QA player or the editor. It drives the real game with virtual input and checks what happened. The first failed check ends the run. Main: CircuitSliceChecks (-circuit-verify <folder>) and ExpeditionHarness (-expedition-net-verify). Explained in: QA & Rehearsals.
CircuitSliceChecks
The Circuit rehearsal. IsometricSlice.Start installs it, it runs its stages, writes verification.txt and quits with 0 or 1. Main: 10 partial files in Assets/Tests/Runtime/CircuitSliceChecks*.cs. Explained in: QA & Rehearsals.
ExpeditionHarness
The network rehearsal. It installs itself after the scene loads and exercises real transports. Main: Assets/Tests/Runtime/ExpeditionHarness.cs and .Network.cs. Explained in: QA & Rehearsals.
QA player also: rehearsal build
A player built with CIRCUIT_QA (and EMBERGROVE_QA for network QA), so the rehearsals are compiled in. Main: IsometricSliceBuild.Build(true), from Bloomfire Circuit ▸ Build Windows rehearsal. Explained in: QA & Rehearsals.
Shipping player
An ordinary player build with no QA code in it. Main: IsometricSliceBuild.Build(false); Tools/Validate-CircuitPlayer.ps1 checks its assemblies afterwards. Explained in: Builds & Tools.
Build identity also: build-info.json, AssemblySha256
The record each build writes beside the player: version, scene, platform, times, build GUID, result, and the hash of the built game assembly. A rehearsal report can be matched to the build that produced it by that hash. Main: BuildIdentity in IsometricSliceBuild.cs. Explained in: Tests README, Builds & Tools.
Batch entry point
A static method that a batch-mode Unity editor runs from the command line with -executeMethod. Main: CircuitPersistenceVerification.RunBatch, CircuitSliceChecks.RunCardPresentationBatch and RunCircuitContentBatch. Explained in: Tests README, QA & Rehearsals.
Suite also: Portable
A named check in the check runner. Portable is the default group, and All adds the optional suites. Main: Tools/Run-Checks.ps1. Explained in: QA & Rehearsals, tools README.
Candidate also: internal preview candidate
A build put forward for review. It needs fresh builds, a rehearsal and an inspection of the shipping assemblies. Main: Tools/Package-Isometric.ps1. Explained in: Internal preview candidate, Builds & Tools.
Guide
A Markdown file that owns the current procedure or rules for one subject. Pages in this wiki link to guides and do not copy them. Main: Docs/Guides/*.md, and the toolkit's Documentation~/*.md. Explained in: Docs/README.md.
Roadmap also: cleanup milestone, owner decisions
The only backlog. It owns priorities, status and decisions, including the cleanup milestone and the open owner decisions. Main: Docs/Release/ROADMAP.md. Explained in: ROADMAP.md.
Offline reference also: handbook
The older generated documentation, a single-file content and code inventory plus the portable Studio handbook, written into the ignored Builds/Documentation. Main: Tools/Documentation/export_wiki.py (--handbook-only for the handbook alone). Explained in: Documentation README, Maintaining.
