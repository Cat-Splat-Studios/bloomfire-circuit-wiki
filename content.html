How content reaches the game

Where cards, dialogue, places, pictures and sounds are authored, how they are checked and staged, and which code reads them while the game runs.

In 60 seconds

  • Three content folders, three loaders. Content/EmberGroveDefault is the replaceable pack, read by ContentPackFiles.Load. Content/Circuit holds the Circuit's sidecar files, read by CircuitContentLoader. Content/Exploration/sector.json is the start-up sector, read by IsometricSlice.Start.
  • Only the pack can be swapped without a build. ContentPackFiles.DefaultRoot picks -content-pack, then persistentDataPath/ContentOverride, then StreamingAssets/Content. The sidecars and the sector are always read from StreamingAssets.
  • The build copies; the repository owns. IsometricSliceBuild validates each folder and copies it into the git-ignored StreamingAssets before every build. The staged copy is never the source.
  • Media is by ID, never by path. media.json registers each picture and sound once. Artwork goes through shared CardArtworkCache leases; the world reads music and voice, and each hosted session reads music and sound-cue overrides, from the pack.
  • Content Studio runs the game's own parsers. Tools/ContentStudio compiles the toolkit's content files with CARDFORGE_HEADLESS and a small UnityEngine stand-in, so a pack that validates in Studio has passed the same ExpeditionContent.Parse and WorldContent.Parse as the game.

Before you start

  • This page explains structure. The field-by-field pack format is owned by the pack contract, the creator workflow by the designer and writer pipeline, and art and menu-role rules by the artist and presentation pipeline.
  • How the loaded content becomes a running Circuit is on World & Journal; how each hosted session reloads it is on Hosted Sessions; what the game saves is on Saves & Settings.

02From authored file to running game

Every path starts in Content/, is checked when the build stages it (the pack and the sector fully; the sidecars for presence and lesson rules) and again as the game loads it, and is read at run time from StreamingAssets or from an override folder.

Authored files to the running game. IsometricSlice.Start reads the sector first and only then calls LoadCircuit; hosted sessions load the pack again from the same root (IsometricSlice.CircuitContentRoot, passed as IsometricCombatBridge.ContentRoot).

  1. Start-up order. IsometricSlice.Start reads StreamingAssets/Exploration/sector.json. LoadCircuit then reads the five sidecars through CircuitContentLoader, calls ContentPackFiles.Load, runs ResolveCircuitDialogue and the artwork lease, checks the guide, dialogue, location, journey and presentation tables, builds a CircuitDefinition, checks the rival decks and finally restores the save. CircuitDefinitionBuilder owns the checks, the definition and the rival check; the presentation check stays on the slice. Any failure sets Error, so a broken pack stops the Circuit before it reads a save.
  2. After the pack. LoadWorldPreferences applies player settings and InitializeCircuitMusic starts the world's music source.
  3. Each hosted session. Every HostedSessionKind (Circuit duel, friendly game, practice, lesson, Versus, settings) runs an ExpeditionApp, whose Start calls ContentPackFiles.Load(sessionContentRoot ?? DefaultRoot()) and then InitializeMedia.
A run with -circuit-verify or -expedition-net-verify ignores the override order: CircuitContentRoot is then always StreamingAssets/Content, so rehearsals play the bundled pack.

03The pack: manifest and documents

manifest.json is a ContentManifest. It names the pack and points at three required documents and one optional one; Load reads only manifest.json and the documents it names; media files are read later by the code that presents them.

Manifest fieldType in codeEffect
Version, Idint, stringParseManifest rejects a version other than 1 and a blank Id or one longer than 96 characters.
Title, Description, Author, ContentVersion, MinimumGameVersionstringIdentity. IsometricSliceBuild.ValidateAndroidContentVersion compares MinimumGameVersion with an Android candidate's version.
CombatFile, WorldFile, MediaFilestring, defaulting to expedition-content.json, world-content.json, media.jsonMust each pass SafeRelativePath.
CircuitCircuitPackDefinition (Version, DialogueFile)Optional. Present means the pack owns its Circuit dialogue; absent means the game uses the bundled StreamingAssets/Content/circuit-dialogue.json.
Why the manifest is scanned by hand for "Circuit"

Unity's JsonUtility cannot tell a missing inline object from an explicit null: both arrive as a default object. Only omission may opt an older pack into the bundled dialogue, so ParseManifest calls HasRootProperty(json, "Circuit"), a small tokenizer that counts top-level property names (so the word inside a description does not count), refuses a duplicate, and requires the value to be an object. If the property is present, Circuit.Version must be 1 and DialogueFile a safe path; otherwise manifest.Circuit is set to null.

What each document owns, and which collections the current Circuit still plays, is the pack documents table; the field rules are the pack contract and its optional Circuit dialogue section.

04Loading a pack: ContentPackFiles

ContentPackFiles is a static class of coroutines. It reads every file through UnityWebRequest, so the same code works on a desktop folder and inside an Android APK, then hands pure definitions to the rest of the game as one LoadedContentPack.

Which folder is the pack

  1. -content-pack <folder> on the command line, made absolute with Path.GetFullPath. This is the creator review shortcut the authoring guide describes.
  2. Application.persistentDataPath/ContentOverride, but only if it contains a manifest.json.
  3. Application.streamingAssetsPath/Content, the staged default pack.

What Load does

StepMemberOn failure
Read manifest.jsonprivate Read, then LoadManifest → ParseManifestfailure(message), stop
Read the combat, world and media files the manifest names, in that orderRead for eachfailure, stop at the first
Read the declared dialogueLoadDialogue → JsonUtility.FromJson<CircuitDialogue> and CircuitRules.ValidateDialogue"Invalid Circuit dialogue: …"
Parse and cross-checkLoadPackParsed: ExpeditionContent.Parse, WorldContent.Parse, JsonUtility.FromJson<MediaDefinition>, then World.Validate(pack), MediaDefinition.Validate and, with dialogue, CircuitRules.ValidateDialogueMediaA parser's exception, or all validation messages joined into one InvalidDataException; its message goes to failure
Identify the combat contentSHA-256 of the combat JSON into ActiveCombatHash and LoadedContentPack.CombatHash—

Paths that cannot escape

SafeRelativePath accepts a forward-slash relative path of at most 240 characters with no \, :, %, ?, #, leading /, empty segment, . or ... Location(root, relative) then builds the URL: for a jar: root (Android) it escapes each segment; for a folder it checks that the full path stays inside the root and that no folder or file on the way is a reparse point (link or junction). Every read of a pack media file (CardArtworkCache, ExpeditionApp.ReadAudio, the Circuit's voice and music) goes through Location; the practice guide's WAVs in StreamingAssets/Circuit/Voice are checked by PracticeNarration's own file-name rule instead.

The parsers

  • ExpeditionContent.Parse(json) maps private authoring DTOs (AuthoredPack, AuthoredCard, …) to a ContentPack, reads enum names strictly (ReadEnum rejects unknown names), runs ContentPack.Validate and CreateCatalog, and throws on any error. Under CARDFORGE_HEADLESS it deserializes with System.Text.Json; otherwise with JsonUtility.
  • WorldContent.Parse(json) maps WorldDto to a WorldDefinition and runs WorldDefinition.Validate. It always calls JsonUtility; Content Studio's headless build supplies that name through Tools/ContentStudio/UnityBoundary.cs. WorldContent.Serialize is the reverse.
  • Under CARDFORGE_HEADLESS, ContentPackFiles keeps ParseManifest, SafeRelativePath, Location and the media schema but leaves out DefaultRoot, Load, LoadDialogue and Read.

05Size caps, timeouts and content hashes

Each limit is enforced where the bytes enter, not in one place. These are the values in code on main.

Menu palette colours are in none of the network hashes (the combat hash, the lobby hash or the fingerprint), so a palette cannot split online play; the review-candidate check does hash media.json. What the network does with the hashes is on Networking.

06The Circuit sidecars and the sector file

The sidecars carry Circuit data the pack format does not model. They are always read from StreamingAssets/Circuit, never from the pack root, so a -content-pack folder cannot change them.

FileRead intoRequired
card-guide.jsonCircuitGuide; must describe every pack card exactly once, and supplies archetypes, starters and opponent encounter IDsYes
locations.jsonCircuitPlaces; every layout must pass SectorNavigation.Validate; also hashed for the lobbyYes
journey.jsonCircuitJourney; learning policy and solo perksYes
practice.jsonRaw JSON kept as practiceContentJsonNo; a failure logs a warning and uses the built-in guide
lessons.jsonCardForge.Lessons.LessonLibraryNo; same fallback
Voice/lines.json and Voice/*.wavPracticeNarration.VoicePackNo; a missing or stale recording leaves the instruction silent

CircuitContentLoader.Read is a coroutine that reads one file and either reports a failure to the slice's Error (required) or logs a warning (optional). Reading never stops early, and the pack loads after the sidecars, so the last failure, the pack's included, is the one shown. Content/Exploration/sector.json is read by IsometricSlice.Start with its own request (not CircuitContentLoader), and a failure sets Error as for a required sidecar; its README explains why the file must stay even though editing it changes nothing a player sees. Designer-facing settings in locations.json are described in designer settings without Unity.

ResolveCircuitDialogue decides where dialogue comes from: the pack's declared document if Load returned one; an error if the manifest declared one that is missing; otherwise the bundled StreamingAssets/Content/circuit-dialogue.json through LoadDialogue.

07Staging into StreamingAssets at build

StreamingAssets/Content, /Circuit and /Exploration are listed in .gitignore. IsometricSliceBuild recreates them from Content/ before every scene creation, build and editor stage; each method validates its inputs before it copies anything.

MethodValidatesCopies
StageSectorSectorNavigation.Validate on sector.jsonsector.json → StreamingAssets/Exploration
StageEncounterContentParseManifest, both parsers, World.Validate, MediaDefinition.Validate, the declared dialogue, and that every non-blank media path names an existing fileEvery pack file except .meta files and dot-named files or folders → StreamingAssets/Content. It overwrites but never deletes, so unrelated staged files stay.
StageCircuitLessonRules.Validate against the pack's catalog and match rules, and that all five sidecars existThe five sidecars and Voice/*.wav plus Voice/lines.json → StreamingAssets/Circuit; deletes the retired StreamingAssets/Circuit/dialogue.json

All three run, in that order, from the menu Bloomfire Circuit ▸ Stage content for editor (StageCircuitContent), from CreateScene, and from Build. An Android build also checks that the staged expedition-content.json hashes to the BuildIdentity.ContentSha256 it computed before staging. The build menus and packaging are on Builds & Tools.

Never edit the staged StreamingAssets copy; the next stage overwrites it. MAINTAINING ownership names Content as the owner of pack data, media and sidecars.

08Media: media.json, artwork leases and audio

media.json is a MediaDefinition: a list of MediaAssetDefinition records (Id, Kind, Path, Volume, Loop, atlas cell, optional Transcript) and one MediaThemeDefinition. Everything else refers to media by ID. A blank Path is a deliberate placeholder.

KindConsumerHow it is used
CardArt, PortraitCardArtworkCache.LeaseTexture plus a sprite cut from the atlas cell (CardArtworkCache.TryCell, one-texel inset for multi-cell sheets). ExpeditionView.ApplyExternalTheme turns CardArt sprites into CardArtworkOverrides by card ID; the Circuit uses them through TravellerPictures.ConfigureArtwork.
ArtworkCardArtworkCache.LeaseTexture only, no sprite: backdrops (Theme.BackdropId), choice pictures (cropped to the atlas cell when drawn) and Waybook art slots.
MusicExpeditionApp.Media and IsometricSlice.AudioA hosted session cross-fades two sources between Theme.MusicMenuId, MusicJourneyId, MusicBattleId, MusicBossId and MusicVictoryId, except when it sits inside the world (UsesWorldPresentation). The world plays one source (looping when the asset's Loop is set): music.circuit, else the journey music, ducked while a voice or practice runs.
VoiceIsometricSlice.AudioPresentCircuitVoice plays a line's AudioId only when MatchesTranscript is true. With the SpokenHelp setting on, CircuitGuideForText finds voice.guide.* records whose transcript equals the focused button's text.
SoundGameAudioDirector.OverrideCueReplaces one built-in cue family loaded from Resources/DuelAudio; the ID is sound.<family> or the bare family name.

Artwork leases

CardArtworkCache keeps one static dictionary of decoded images keyed by URL. Each caller takes a Lease with Acquire(root, media); the lease borrows entries (incrementing Users), owns its own sprites, and on Dispose releases them. The world (IsometricSlice.worldArtwork) and each hosted session (ExpeditionApp.mediaArtwork) hold separate leases, so a battle inside the world reuses the world's textures without decoding them again.

sequenceDiagram
  participant W as IsometricSlice

  W->>L1: Load()

Two leases sharing one decoded image. A download in flight is owned by the shared entry, not by either coroutine, so closing one lease does not cancel the other's image.

The practice guide is separate from media.json: PracticeNarration reads StreamingAssets/Circuit/Voice/lines.json and matches each line's Text to the current practice instruction. Artist rules for portraits and recordings are in Circuit speaker portraits and recordings and the pack contract's media section.

09Menu roles and palettes from the pack

A pack can recolour the menus without code. The colours live in media.json under Theme; the code that applies them is DuelUi.MenuColour, one static table read by both uGUI stacks.

  • Schema. MediaThemeDefinition.MenuPalettes holds MenuPaletteDefinitions; MenuPalette names the one in use and SelectedMenuPalette finds it (empty means none). ThemeColour(role) returns the palette's colour for one of the five Theme roles, else the Theme's own. WaybookPalette lets a palette choose the book's garden or berry palette.
  • Allowed roles. MenuPaletteDefinition.ThemeRoles (the five Theme colours) and MenuPaletteDefinition.MenuRoles (the settable, non-High-Contrast roles in DuelUi.MenuColour). MenuPaletteDefinition.Validate rejects anything else, so a bad palette fails the pack load.
  • Trying one without editing. -menu-palette <id> sets ContentPackFiles.MenuPaletteOverride; LoadPackParsed writes it into Theme.MenuPalette before validation.
  • Applying. DuelUi.MenuColour.Use(palette) is called by IsometricSlice.LoadCircuit and ExpeditionView.ApplyExternalTheme as each stack loads its pack. UseHighContrast is called from ExpeditionApp.ApplyRuntimePreferences. Resolve resets every role to its captured literal (Builtin), then, unless High Contrast is on, writes the palette's colours, keeping each role's own alpha.
  • The Waybook. Theme.Waybook is a WaybookPresentationDefinition (copy, palette, mascot, note style and ArtSlots bound to ArtRoles); IsometricSlice.Waybook reads it as WaybookStyle.

The rules for which role a menu site takes, and what a palette does not reach yet, are owned by Menu roles. How the menus themselves are built is on UI & Menus.

10Content Studio

Tools/ContentStudio is one .NET 10 project (ContentStudio.csproj, assembly EmberGrove.ContentStudio). It compiles the toolkit's Functional, Core, Progression and Circuit folders and the three content files by path, with CARDFORGE_HEADLESS and the UnityBoundary.cs stand-in for JsonUtility and Resources.

Desktop host

Built with -p:StudioDesktop=true (adds STUDIO_DESKTOP, WinForms and WebView2). DesktopHost intercepts the page's requests to https://cardforge.invalid in process and passes them to Program.Request; no socket is opened. Default folder: Documents/CardForge/WorkingPacks/EmberGrove.

Loopback server

The default build, or the desktop executable with --serve. RunServer starts an HttpListener on http://127.0.0.1:47831 (or --port), refuses non-loopback callers and routes to the same Program.Request.

EndpointDoes
GET /api/packThe documents (StudioDocuments), a SHA-256 Revision, the folder and the schema lists (enum names, palette and Waybook roles taken from CardForge)
POST /api/validatePackValidation.Run: Studio's own field checks plus ExpeditionContent.Parse, WorldContent.Parse, World.Validate and CircuitRules.ValidateDialogueMedia; returns errors, warnings and issues that point at a record and field
POST /api/saveRefuses invalid drafts and a stale ExpectedRevision; copies every touched document into .studio-backups/<UTC>, writes *.studio-tmp, moves each into place, and restores the old bytes if any step fails
POST /api/exportA ZIP of the documents and every referenced media file
GET/POST /api/mediaPreview a media file; import one (refuses different bytes at an existing path)

Every /api/ call needs the session token (the X-Studio-Token header, or a token query value on a GET), which WebResource writes into the page. Studio is stricter than the game in places: CheckManifest requires the canonical document names, CheckCircuit requires the dialogue file to be circuit-dialogue.json, and documents are capped at 4 MiB instead of 8.

ScriptDoes
Start-Studio.ps1In the repository: regenerates the handbook and runs the project from source on Content/EmberGroveDefault itself (so a save edits the canonical pack); -Browser uses the loopback server. Outside the repository: runs the published executable on the working folder.
Publish-Studio.ps1A self-contained single-file win-x64 build into a new, empty folder (default Builds/CardForgeStudio), with sample/ copied from the pack, the README, the handbook and optional manuals
check_current_catalog.ps1The Studio suite of Tools/Run-Checks.ps1

Controls, recovery and boundaries are owned by the Studio README; the transport and API contract by Studio workspace and transport; the creator loop by Author, preview, validate, save.

11CircuitStudio and the Card Workshop

Tools/CircuitStudio is not a .NET project. It holds two offline HTML tools that open a JSON file and download an edited copy (they never write the source), their Node checks, and a launcher that runs Content Studio on the canonical pack.

FileWhat it is
index.html, studio.js, dialogue-model.jsCircuit Studio — Dialogue: opens circuit-dialogue.json, edits speakers and conversations, previews branches against a player's progress, downloads the result. Content Studio owns pack dialogue editing; this page keeps the branch simulation.
lessons.html, lessons.jsThe lesson workshop: opens Content/Circuit/lessons.json and a card catalog, validates, downloads lessons.json to be copied back by hand
check.cjs, lessons-check.cjsThe DialogueModel and LessonModel suites of Tools/Run-Checks.ps1
Start-CardWorkshop.ps1, Open-CardWorkshop.cmdBuilds Content Studio from current sources into Temp/CurrentCardWorkshop/<fingerprint> and serves Content/EmberGroveDefault on loopback from port 47841; -Stop stops the process it recorded in session.json

In Unity, CardForge ▸ Current Card Workshop opens CurrentCardWorkshop, an EditorWindow that lists the catalog with ExpeditionContent.Parse, edits the table presentation prefab, and starts Start-CardWorkshop.ps1 from its Open rules in Content Studio button.

12Loose ends seen from this page

Structural facts a fixer should know. The ranked list of problems is on Findings.

  • Unused loaders. ExpeditionContent.Load and WorldContent.Load read Resources/Expedition/…; nothing on main calls ExpeditionContent.Load, and the game's Resources/Expedition folder holds only ExpeditionTheme.asset.
  • Global statics. ContentPackFiles.ActiveCombatHash and the palette inside DuelUi.MenuColour are process-wide and belong to whichever pack loaded last; ContentPackFiles.MenuPaletteOverride is a settable static read from the command line.
  • Rules written twice. Studio's CheckMenuPalettes and CheckWaybook in Program.cs repeat the rules of MenuPaletteDefinition.Validate and WaybookPresentationDefinition.Validate so each message can name a field; only the role lists are shared.
  • Two override stories. The pack can be replaced at run time; the sidecars and sector cannot, yet card-guide.json must describe exactly the pack's cards, so a review pack that changes the card set fails at start-up.
  • Repeated loads. Every hosted session reloads and revalidates the whole pack (Hosted Sessions).
  • A stale guide. Docs/Concepts/AUDIO_DESIGN.md (Integration) still names DuelAudioDirector; the class on main is GameAudioDirector.
