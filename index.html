The structure wiki

Bloomfire Circuit

How the code is put together on main today: the reusable rules, the Unity game and the tools around them, drawn as diagrams, with the complexity work and the structural problems that are left, so you can choose what to fix next.

Unity 6000.5.5f1 · project Game/EmberGrove toolkit CardForge 0.7.0 · pure C# rules one build scene · CircuitJourney.unity read from main, through git diagrams in Mermaid, offline

In 60 seconds

  • What this wiki is. A map of the current code structure, for the owner and future maintainers. It explains how the pieces connect, draws them, reports the complexity work and lists the structural problems that remain. It describes what is built. Plans, status and decisions live in the roadmap, never here.
  • Three layers. The CardForge toolkit holds the rules as plain C#. Only its content loader uses the Unity engine, plus one editor-only build hook. The Unity project Game/EmberGrove turns those rules into a world, menus, matches and saves. Tools/ compiles the same toolkit source files into .NET checks, the Content Studio and the relay. See §01.
  • One way to change state. A rule function returns a Result<T>, and the game keeps the new state only when it succeeds. The adventure does this in IsometricSlice.ApplyCircuit. A local match calls CombatRules.Resolve from ExpeditionApp. A networked match resolves inside ExpeditionAuthority.Receive. See §02.
  • Which document answers what. This wiki covers structure. Docs/Guides covers procedures and rules. Docs/Release/ROADMAP.md holds priorities, status and decisions. README.md holds current scope, and AGENTS.md the contribution rules. Pages here link to those files and do not copy them.
  • Where to go next. If you are new to the code, read the Codebase Tour and then the Glossary. If you are choosing a fix, read Findings and then Complexity. If you have one task in mind, use the §04 reference card.

Before you start

  • You do not need Unity running to read any page here. Every claim is about files on main.
  • To press Play as you read, use Unity 6000.5.5f1, open the folder Game/EmberGrove (not the repository root) and open Assets/Scenes/CircuitJourney.unity. The README and the one-time setup cover the rest.
  • The developer guide's source map owns the code boundaries, and its product-name table explains why one game carries several names. This wiki links to both rather than copying them.
  • If you meet a word you do not know, look it up in the glossary.
  • This site is published from the private CardGame repository (how). Links to source files open that repository, so they work only for people with access to it.

01Three layers

All code sits in one of three places, and the dependencies point one way. The game and the tools use the toolkit. The toolkit references neither of them.

Toolkit rules

Toolkit/Packages/com.catsplat.cardforge, a Unity package with seven runtime assemblies. It holds the combat reducer CombatRules, the adventure rules CircuitRules, the lesson checks LessonRules, navigation in SectorNavigation, pack loading in ContentPackFiles, and multiplayer in ExpeditionAuthority and ExpeditionNetworkSession.

Every runtime assembly except CardForge.Content sets noEngineReferences.

Unity game

Game/EmberGrove has no assembly definitions, so its code compiles into Assembly-CSharp, with an editor assembly for Assets/Editor. Two parts do the work. IsometricSlice owns the world, the Waybook, the journal and the save. ExpeditionApp and ExpeditionView host one session: a duel, a practice, a lesson, Versus or Settings.

IsometricCombatBridge joins those two parts.

Tools

Tools/ holds .NET 10 projects that compile toolkit source files (and a few game files) by path, rather than referencing assemblies. They are the check suites, CardForge Content Studio, and the relay with its trusted service.

Tools/Run-Checks.ps1 runs the checks.

02How a player action travels

A press in the world and a press in a match take different routes, but both end the same way. A pure function in the toolkit decides, and the game keeps the result only when that function succeeded.

Hand-drawn from IsometricSlice.Circuit.cs (ApplyCircuit, PlayCircuitDuel), ExpeditionApp.cs (Submit, ResolveLocal, Present), ExpeditionApp.Network.cs (PresentNetwork), ExpeditionNetworkSession.cs (Submit, ProcessCommand) and ExpeditionAuthority.cs (Receive). Box borders give the layer: teal for the Unity game, bronze for the toolkit, mint for the tools. The dashed edge is the view the authority sends back to each seat.

  1. In the world. Walking, the Waybook and the journal pages belong to IsometricSlice. A choice that changes progress calls one CircuitRules transition, such as BeginDuel, ResolveDuel or ChooseReward, and passes the Result<CircuitState> to ApplyCircuit. On failure, ApplyCircuit shows the RuleError message. On success it replaces the state and saves. When the caller asks it to require a save and the save fails, it puts the previous state back.
  2. Into a match. PlayCircuitDuel records a pending duel with a receipt. IsometricCombatBridge.Play then creates a "Hosted session" object and adds an ExpeditionApp configured for that table. Practice, lessons, Versus and Settings use the same bridge, with a different HostedSessionKind.
  3. In the match. ExpeditionView turns pointer, keyboard and pad input into selections and commands, and each CombatCommand reaches ExpeditionApp.Submit. A local match resolves it with CombatRules.Resolve and animates the result. A networked match sends it through ExpeditionNetworkSession, and the side that holds the full match resolves it in ExpeditionAuthority.Receive. That side is the host for LAN and relay games, and TrustedMatchApplication for the trusted service.
  4. Back to the world. The finished outcome goes back into CircuitRules.ResolveDuel with the same receipt, through ApplyCircuit, so a repeated callback cannot grant a reward twice.
Owned elsewhere. The step-by-step command contract is in One accepted command. The adventure transitions and receipts are in the Circuit rules README. Who may resolve a networked command is in Networking, Current authority boundaries. The wiki pages that follow each route are Rules Engine, World & Journal, Hosted Sessions and Networking.
